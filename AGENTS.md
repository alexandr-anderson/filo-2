# AGENTS.md

Общие правила проекта для AI-ассистентов (Claude Code, Cursor, Codex) и людей. Claude-специфичное лежит в `CLAUDE.md`.

## Проект

Интернет-магазин профессиональной косметики для волос **Filó Professional** (Бразилия) для эксклюзивного дистрибьютора в России.

- Покупатели: в первую очередь мастера и салоны, также частные покупатели.
- Розничная и оптовая цена видны всем. В корзине показываются обе суммы.
- Онлайн-оплаты нет: корзина формирует текст заказа и открывает чат магазина в Telegram (`t.me/...`). Сервера и бота для заказов нет.
- Товары, фото, категории, цены и наличие ведутся в собственном админ-кабинете в табличном стиле (`/admin`). Google Таблиц нет.
- План и статус задач: `plan.md`. Решения: `docs/decisions.md`. Бренд: `docs/brand-guidelines.md`.

## Стек (предложен, подтверждается в S0-T4)

| Слой | Выбор | Почему |
|---|---|---|
| Фреймворк | Next.js (App Router) + TypeScript | Серверный рендеринг для SEO, витрина и кабинет в одном проекте |
| Стили | Tailwind CSS + токены из `design-system/tokens.css` | Один источник цветов и радиусов |
| БД | SQLite + Drizzle ORM | Малый объём данных, простой бэкап одним файлом |
| Фото | Диск сервера, обработка `sharp` (WebP, несколько размеров) | Отдельное хранилище не нужно |
| PDF прайса | Генерация на сервере (`@react-pdf/renderer`), шрифт с кириллицей | Без headless-браузера на сервере |
| Excel | `exceljs` | Импорт и экспорт прайса |
| Тесты | Vitest, Playwright для сквозных сценариев | |
| Деплой | Docker + Caddy (HTTPS) на VPS в России, ежедневный бэкап | Данные хранятся в РФ |

Новые зависимости добавляем только с обоснованием в `docs/decisions.md`.

## Команды

Заполняется после S0-T4 (каркас проекта). Ожидаемый набор:

```bash
npm run dev        # локальный сервер
npm run build      # продакшен-сборка
npm run lint       # ESLint
npm run typecheck  # tsc --noEmit
npm test           # Vitest
npm run db:migrate # миграции
npm run db:seed    # тестовые данные
```

## Правила кода

- TypeScript strict, без `any` без причины. Серверные компоненты по умолчанию, `'use client'` только там, где нужна интерактивность.
- Цвета, радиусы и шрифты берём только из токенов. Хардкод цветов в компонентах запрещён.
- Деньги храним целыми рублями (`integer`), форматируем `Intl.NumberFormat('ru-RU')`.
- Артикул (`sku`) уникален и является ключом варианта товара.
- Все данные из кабинета и форм валидируем на сервере (zod).
- Секреты только в `.env`, в репозитории только `.env.example`.
- Иконки только из Phosphor, не рисуем SVG вручную.

## Правила интерфейса и текстов

- Язык интерфейса русский. Обращение на «вы», буква «ё», кавычки «ёлочки».
- Без длинного тире `—` в текстах интерфейса: точка, запятая или двоеточие.
- Название бренда: «Filó» в логотипе и заголовках, «Filo» в URL и коде.
- Сначала мобильная версия. Кнопки и поля не меньше 44 px, видимый фокус, контраст по WCAG AA.
- Тон: экспертный, тёплый, конкретный (см. `docs/brand-guidelines.md`). Не выдумываем цифры и отзывы, недостающее помечаем `[заглушка]`.

## Персональные данные и юр. требования

- Форма заказа отправляет данные в Telegram клиента, на сервере ПДн покупателей не храним.
- Чекбокс согласия на обработку ПДн (152-ФЗ) обязателен, ссылка на политику рядом.
- Сервер и бэкапы находятся в России.

## Git

- Ветка `main` всегда рабочая. Задачи делаем в ветках `s2/catalog-filters`, `fix/cart-total` и т.п.
- Сообщения коммитов на английском, в повелительном наклонении: `Add catalog filters`.
- Не коммитим: `docs/client/`, `storage/`, `tmp/`, `.env`.
- Пуш и деплой только по явной просьбе.

## Как работать с задачами

1. Берём задачу из `plan.md` по ID (например, `S2-T4`).
2. Делаем её в отдельной ветке, проверяем `lint`, `typecheck`, `test`.
3. Отмечаем `[x]` в `plan.md`. Если появилось новое решение, добавляем запись в `docs/decisions.md`.
4. Всё, что выходит за рамки КП, отправляем в «Бэклог» в `plan.md`, а не делаем молча.
