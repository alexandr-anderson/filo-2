# CLAUDE.md

@AGENTS.md

Ниже только то, что касается Claude Code. Общие правила проекта в `AGENTS.md` (подключён выше).

## Перед началом задачи

1. Найди задачу в `plan.md` по ID и прочитай её «Готово, когда».
2. Проверь `docs/decisions.md`: решение могло быть уже принято.
3. Если задача упирается в 🔒 (ответ клиента), не придумывай ответ: спроси пользователя или поставь `[заглушка]`.

## Скиллы проекта (`.claude/skills/`)

| Когда | Скилл |
|---|---|
| Новая страница или раздел интерфейса | `ui-ux-pro-max` (`--design-system`, затем `--domain ux`) |
| Верстаем витрину, проверка «не шаблонно ли» | `design-taste-frontend`: прогнать финальный чек-лист перед сдачей |
| Цвета, шрифты, тон текстов | `brand` (`docs/brand-guidelines.md`) |
| Изменили токены | `design-system`: правим `design-system/tokens.json`, затем `node .claude/skills/design-system/scripts/generate-tokens.cjs --config design-system/tokens.json -o design-system/tokens.css` |
| Компоненты на Tailwind | `ui-styling` |
| Баннеры, обложки для соцсетей | `banner-design` |
| Логотип, фирменный стиль | `design` |
| Проверить план или решение на прочность | `grilling` (задаёт вопросы пользователю, ничего не делает до ответа) |

## Проверка своей работы

- Код: `npm run lint && npm run typecheck && npm test` перед тем, как сказать «готово».
- Интерфейс: запусти dev-сервер и посмотри страницу в браузере на ширине 375 px и 1440 px. Без проверки в браузере не говори, что вёрстка работает.
- Тексты интерфейса: нет `—`, есть «ё», нет выдуманных цифр.

## Не делать без явной просьбы

- `git push`, деплой на сервер, отправка чего-либо клиенту.
- Новые зависимости и смена стека (сначала запись в `docs/decisions.md`).
- Работы за рамками КП: предложи их в «Бэклог» в `plan.md`.
